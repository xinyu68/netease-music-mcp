# 架构与维护

## 数据路径

```text
Codex / 小车桥接（MCP 客户端）
             │ stdio JSON-RPC：意图、控制、状态
             ▼
src/server.mjs → mcp-server.mjs（25 个工具、参数校验）
             ├─ account.mjs → auth.mjs（本地会话）
             │       └─ api-client.mjs → api-worker.mjs → 网易云账号 API
             ├─ music-search.mjs → 合并收藏与公开曲库候选、排序与来源状态
             │       ├─ account.mjs → 收藏 ID 快照、分批详情与短时内存缓存
             │       └─ netease.mjs → 公开搜索、详情、歌词只读接口
             └─ playback-controller.mjs（队列、状态机、取消与去重）
                     ├─ media-source.mjs → 正常账号授权音源
                     └─ mpv-engine.mjs → 私有 IPC → mpv → 默认音频设备
                                                        ▲
                                                        └─ HTTPS CDN 音频
```

无 HTTP 服务、无公开调试端口、无桌面客户端自动化。API 库在单独 worker 中运行，避免底层日志污染 MCP 的 stdout 或泄露请求。父子进程通过 IPC 通信，worker 只允许已定义的 API 方法；不启动上游通用 API HTTP 服务。

`api-methods.mjs` 区分只读与写入 allowlist。只有只读请求超时才丢弃 worker 并重试一次；收藏写入不自动重试，由账号层读取前后状态核实。主动关闭会阻止重试，其他并发请求被重置时如实返回失败，不做无限请求或假成功。

## 播放控制

状态机与外部引擎分离。普通写操作串行，最多 32 个待处理请求；停止可以越过慢请求，取消旧操作并提高代次。异步返回、进度和曲尾事件必须匹配当前流，避免已停止的旧曲目重新发声。

每个操作有超时，去重历史有数量和时间上限。MCP 控制请求不会传输音频字节；歌词工具会返回显示数据。播放器前向缓存默认 4 MiB、回看缓存 1 MiB，有独立解码器和设备缓冲，不能据此推算 ESP32 内存占用或本机进程总内存。

播放确认要求实际音频输出就绪、未暂停/空闲/缓冲，并观察到时钟推进；这比只确认发出播放命令更可靠，但不能代替人耳确认扬声器音量或外部设备接线。

停止会取消准备中的播放、卸载音源、进度归零。暂停只保留位置；继续可按到期情况刷新音源。源到期恢复最多一次；普通网络失败如实报错。服务关闭时只关闭自己拥有的 mpv 和 API worker。

`queue.mode` 保留普通/心动推荐来源语义，`queue.playbackMode` 单独表示顺序、随机、单曲循环。随机使用索引排列及游标，不改变上游歌单；手动前后切歌复用该排列，心动补充与窗口裁剪同步调整索引。自然曲尾的单曲重播仍经过代次检查、授权解析及真实进度验证，不通过 mpv 全局循环开关绕过控制器；停止可取消正在重播的请求。

## 安装与维护边界

Node 依赖由 `package-lock.json` 锁定，API 使用固定 Git 提交的 HTTPS 源码 tarball，lockfile 校验完整性，不需要用户的 GitHub SSH 密钥。Windows mpv 使用上游 v0.41.0 稳定发行页面的 mingw-w64 CI 附件，安装前检查 SHA-256；附件内还有一层 ZIP，脚本解开后实际执行 --version 验证。源地址不可用时安装失败，不静默换包，不再使用滚动删除资源的 git-release。

## 插件包装与首次准备

`plugin/` 维护 portable 与 Codex 兼容清单、Skill 和一个不依赖第三方包的启动器。build-plugin 把包装与选定运行源码组合到 `dist/plugin`；市场目录只指向该生成目录，不把整个仓库、个人配置或依赖复制进 Codex 缓存。

`node scripts/setup.mjs --plugin` 根据同一份源码和 lockfile 的指纹，在用户状态目录生成独立运行目录，安装生产依赖、准备 mpv 与登录窗口。只有依赖步骤成功才写就绪标记；启动器检查指纹、SDK、登录窗口和播放器是否存在，未准备时只输出安装提示，不自动下载或登录。启动器随后加载这个运行目录中的同一 src/server.mjs。

每次升级是新目录，登录文件仍在外部公共状态目录。源码目录和插件缓存的同版运行源码产生相同指纹。setup 使用独占锁，避免并发安装；强制终止后的残留锁需先确认进程退出再处理。共享下载缓存只保存有哈希的播放器压缩包，不存歌曲或账号信息。

mpv 独立程序不随源码包分发。安装脚本不会执行文件关联 BAT；不加载用户 mpv 配置、脚本或 ytdl。生产使用前应保持依赖复查，但不要盲目执行 `npm audit fix --force` 改变已验证 API 协议。

源码交接包使用显式清单，包含 lockfile、测试、文档和登录源码，排除凭据、本机配置、依赖、mpv 及历史原型。GitHub 仓库分发开源源码，npm 发布与云端部署不在本项目安装流程内。Windows 干净目录安装验收记录见本机验收文档。

## 后续接 ESP32

当前 `MpvEngine` 负责电脑播放。将来应新增板端音频输出适配器，在受控数据层解码/转码及传送音频；复用账号、搜索、歌词、授权解析及会话控制的设计。不通过模型传音频，也不把临时 URL 永久烧录。音频/语音抢占、歌词与真实播放位置同步、频谱、内存与断线恢复都需要真实板端验收，当前未实现这些适配器。
