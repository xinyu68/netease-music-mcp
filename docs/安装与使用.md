# 安装与使用

## 先选择入口

普通 Codex 用户推荐本地插件：音乐 Skill 负责组织点歌流程，MCP 负责真实操作。其他 MCP 客户端或希望手动配置的用户选择独立 MCP。两者使用同一源码，不需要硬件，播放器也不需要打开窗口。

## 一、准备电脑

1. 安装 Node.js >=22.13，重新打开终端，确认 `node --version` 和 `npm --version` 可执行
2. Windows 目前支持 x64。登录窗口需要 [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)，以及系统自带的 .NET Framework C# 编译器
3. Mac 为预览支持：先安装 Xcode Command Line Tools（`xcode-select --install`）。准备 mpv，或安装 Homebrew 后让 setup 执行 `brew install mpv`
4. 下载项目 ZIP 解压，打开该文件夹的终端。源码包里的 `package.json` 所在目录就是项目根目录

Git 仅在你选择 git clone 时需要，不是 ZIP 安装或音乐运行的必需条件。项目运行不需要原作者的电脑路径、上传项目、网易云客户端、额外的模型 API Key 或开发者的登录文件；Codex 自身按你的正常账号和权限运行。

## 二、插件安装（推荐）

### 有 Codex CLI

先确认 `codex plugin --help` 可执行，再运行：

```text
node scripts/setup.mjs --plugin --install-plugin
```

脚本会准备本机运行目录，登录并自检，然后调用已验证的 CLI 命令：

```text
codex plugin marketplace add "/项目绝对路径"
codex plugin add netease-music-mcp@netease-music-local
```

注册只添加此项目的本地插件源，不覆盖其他插件或 MCP 配置。当前验证的 CLI 为 0.153.4；如版本的子命令不同，请升级到支持本地插件的版本，或使用下面的桌面流程，不盲目套用其他版本的 install/add 命令。

### 只有 Codex 桌面

运行：

```text
node scripts/setup.mjs --plugin
```

在 Codex 桌面中打开该项目文件夹，按正常方式信任项目并重新加载应用，在插件目录查看项目的“网易云音乐本地插件”源，安装“网易云音乐”。仓库的 `.agents/plugins/marketplace.json` 指向生成的 `dist/plugin`。如果你的桌面版本未显示本地源，可安装 Codex CLI 后按上面的两条注册命令操作；当前没有验收所有桌面版本的 UI 差异。

插件安装完成后开始新聊天。可说：“播放我喜欢的音乐”“搜索某首歌”“暂停”“下一首”。普通播放不需要先读取完整收藏列表。

### 只拿到了插件包

包内含源码、MCP 配置和 Skill，没有 Node 依赖、播放器或任何登录信息。若宿主安装后提示未准备，在实际插件根目录运行：

```text
node runtime/scripts/setup.mjs --plugin
```

由 Skill 引导时，也使用这条命令。依赖写入用户状态目录，不在 Codex 插件缓存中执行 npm install 或修改源码。准备后重新加载聊天。

## 三、首次登录

setup 默认检查已有会话。没有会话或会话失效时，打开网易云官方网页，由你本人扫码/验证。完成后保存到你本机的状态目录，再实际请求账号信息确认成功。

不需要购买会员才能使用项目；免费账号按自身权限播放，会员账号也仍受具体曲目权限限制。登录不同电脑时重新登录，不搬运原作者或旧电脑的 DPAPI 文件。

不方便现在登录时：

```text
node scripts/setup.mjs --plugin --no-login
```

之后去掉 `--no-login` 再执行，会复用已经准备好的运行目录。取消登录不会删除旧凭据，不会换用别人的账号。

## 四、独立 MCP

```text
node scripts/setup.mjs
node scripts/print-mcp-config.mjs
```

将第二条命令打印的配置接入 Codex 或其他 stdio MCP 客户端。执行命令是 Node，参数是项目中的 `src/server.mjs`；不使用 HTTP 地址。MCP 客户端启动/关闭该子进程，音频经本机 mpv 播放。

每个服务进程有独立队列和播放器。不要同时把插件和独立 MCP 接到同一个聊天；若多个应用需要控制同一条队列，应由你自己的共享桥接管理同一个 MCP 实例。

## 五、升级与移动目录

- 新源码版本：重新运行首次 setup 命令。插件运行目录按版本和源文件指纹区分，不把半成品认成安装成功
- 首次准备成功后再更新插件；有新 Skill 或 MCP 配置时重新安装/加载插件并新建聊天
- 插件缓存中的 Skill、启动脚本和源码来自同一版本；旧的运行目录保留，登录凭据在外部状态目录复用
- 移动源码目录后重新注册本地插件源；独立 MCP 要重新生成绝对路径配置
- 自定义状态目录或配置文件时，设置 `NETEASE_MUSIC_STATE_DIR` / `NETEASE_MCP_CONFIG`，并保证准备命令与启动 Codex 的环境一致。脚本不会自动更改系统或用户环境变量

## 六、排障

| 现象 | 处理 |
| --- | --- |
| `node` / `npm` 找不到 | 安装 Node.js 并重新打开终端 |
| `codex plugin` 不存在 | 更新支持本地插件的 Codex CLI，或使用独立 MCP |
| 插件提示 first-time setup | 先执行 `node scripts/setup.mjs --plugin`，再加载新聊天；不要直接在缓存目录手动 npm install |
| 找不到 mpv 或下载失败 | 重新准备；Windows 固定源为 mpv v0.41.0 稳定发行附件并验证 SHA-256；网络必须能访问 GitHub |
| WebView2 Runtime 缺失 | 安装微软 Runtime，再重试；脚本不会修改系统安全设置 |
| 页面加载失败/取消登录 | 网络恢复后重新执行 setup；取消后停止，不自动切换其他登录方式 |
| `LOGIN_REQUIRED` | 重新执行对应入口的 setup，在官方页面完成登录 |
| `API_TIMEOUT` | 运行层已重建 API worker 并重试一次，仍失败请稍后再试；不要把元数据返回成功当成已播放 |
| 无权、试听或保护资源 | 换一首账号有权播放的歌曲；不提供解锁 |
| verified/playing 正常但听不见 | 检查当前输出设备、播放器音量及系统静音；项目不擅自切系统设备 |
| `setup.lock` 已存在 | 先确认另一安装是否仍在运行；如果上次被强制关闭且该进程已退出，只删除用户状态目录里的 `setup.lock` 后重试，不删除 session.dpapi |

要检查前置条件而不安装：`node scripts/setup.mjs --plugin --check`。独立 MCP 的在线自检可用 `node scripts/doctor.mjs --online`；插件则由 setup 在准备的运行目录中执行自检。

首次安装访问 npm、GitHub 和微软 NuGet；音乐运行访问网易云 API 和歌曲 CDN。不要把 Cookie、会话文件或带签名的歌曲 URL 发到日志、聊天、Issue 或源码仓库。
